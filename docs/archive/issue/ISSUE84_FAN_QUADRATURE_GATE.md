# Fan quadrature gate (issue #84, task 1)

Generated by `tools/issue84/render_fan_gate_t1_doc.py` from `docs/issue84/fan_quadrature_gate.json`.

## 1. The defect

`limits()` measured the quadrature gate by evaluating the field at a coarse and a refined Gauss order and differencing the two. The projection fan integrator ignored the `order` argument entirely and always integrated with `fan_order`/`fan_strips`, so the gate compared a configuration with itself and reported `quadrature_error == 0`. Points that legacy Duffy rejected for quadrature reasons (the 7 rows of the frozen gate set) passed silently, and the epsilon gate was reported as the only active gate.

Fix: the fan evaluator now carries an explicit refinement configuration (`fan_refinement_order`, `fan_refinement_strips`, default `max(48, 2*fan_order)` and two strips) plus `quadrature_arguments(order)` / `quadrature_plan(order)`. `limits()` builds the base sample at the production fan and the refined sample at the refinement fan, records both labels in the snapshot, and raises when the two configurations coincide:

```text
ValueError: projection_fan refinement must differ from the base fan configuration
ValueError: quadrature gate would compare a configuration with itself
```

Legacy Duffy keeps its `order`/`2*order` construction unchanged, and `analytic_edges` still reports an identically zero quadrature gate because it has no quadrature to refine.

## 7. What this does not establish

- The fan gate is a self-difference, not an error bound: a point can have a small gate and a larger true error, and section 4 is the only place where the true error is measured.
- Cost is reported, not optimised: the fan remains roughly 3x the legacy path per target, and the production fan is not free.
- The near/far split that task 2 asks for is a separate opt-in evaluator (`projection_fan_adaptive`) and is not enabled here.
